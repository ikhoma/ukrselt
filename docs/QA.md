## 6. Виправлено після перевірки Івана (31.10)
Прелоадер зависав на повільній мережі: шторка чекала події `load` (усі картинки), а SMIL-анімація лого у вбудованому SVG теж стартує лише після `load`. Тепер шторка піднімається через ~2 с від початку навігації, не чекаючи картинок; лого анімується через CSS; запобіжник — шторка зникає сама через 6 с, якщо JS не спрацював. Перевірено з картинками, що вантажаться 8 с.
Урок: перевіряти на deploy-preview і з уповільненою мережею, а не лише на локальній збірці.

Доопрацьовано за рішенням Івана (31.10): хрест заповнюється за реальним прогресом критичного (фото Hero, оверлей, шрифт), але не швидше ніж за 1 с; 1 с тримається; далі лого гасне за 200 мс і шторка їде вгору (~520 мс). Запобіжник 6 с на критичне, CSS-запобіжник без JS — 8 с. Перевірено: без затримки шторка йде на ~2.1 с; з фото Hero, що вантажиться 3 с, хрест стоїть на 2/3 і доходить до кінця, коли фото прийшло.

## 8. Баг прелоадера на повільній мережі (31.10, звіт Івана)
**Симптом:** лого без зуба (лише текст) → зникає → кілька секунд сірий екран → анімація «перезапускається».
**Відтворено** локально сервером, що віддає HTML шматками по 1.4 KB кожні 250 мс (`/tmp/slowsrv.py`).
**Причини:**
1. SVG лого вбудований у HTML і малювався по частинах, поки HTML приходив (12 контурів за ~1.3 с, текст першим).
2. CSS-запобіжник (8 с від першого показу) піднімав шторку посеред завантаження HTML; коли HTML довантажувався, модуль анімацій вимикав запобіжник — шторка поверталась і анімація йшла вдруге.
**Виправлення:** лого видно лише коли SVG прийшов повністю; шторкою керує інлайн-скрипт одразу після неї (стартує з першим шматком HTML), CSS-запобіжника немає, шторка піднімається один раз; ліміт очікування (6 с) рахується від моменту, коли HTML розібраний. Знайдено і виправлено заразом: крива заповнення на кінці давала 0.99999…, і шторка не піднімалась.
**Перевірено:** швидко — заповнення 1 с, шторка на ~2.1 с; повільно (HTML 20 с) — шторка тримається до кінця HTML і піднімається один раз, без повтору.
**Відоме обмеження:** поки HTML приходить, синій хрест не заповнюється (прогрес рахується з моменту, коли HTML розібраний).

## 10. Фікси з код-рев'ю (02.11, docs/code-review-2026-11-01.md)
- **Форма: швидке заповнення більше не губить заявку.** Раніше заявку, заповнену швидше за поріг (автозаповнення браузера), тихо відкидали. Тепер вона надсилається в Telegram з позначкою «⚠️ Заповнено за X с — можливо бот або автозаповнення». Honeypot (`company`) як і раніше відкидається мовчки. Перевірено: elapsed=900 → `{"ok":true,"dryRun":true}`, honeypot → `{"ok":true}`.
- **Прелоадер не залежить від JS-модуля.** Старт прогресу по `readystatechange` (а не DOMContentLoaded, який чекає deferred-модулі) + жорсткий ліміт 15 с. Перевірено: JS затримано на 20 с — завіса піднялась на ~2,9 с при readyState=interactive.
- **Скрол не скидається, якщо користувач уже гортав.** `scrollTo(0,0)` на load виконується лише без хешу і без вводу (wheel/touch/key/pointer). Перевірено (картинки затримано на 6 с): прокрутив до load → 2257 → після load 2400 (не скинуто); без вводу → 0 → 0.

# ADR-0003: Content collections і i18n з запасом під нові локалі

**Status:** Accepted (Іван, 30.10.2026)
**Date:** 2026-10-30
**Deciders:** Іван

## Context
- `/team/*`: однаковий шаблон, різна кількість блоків `benefit` (1–3); лікарі додаватимуться.
- `/services`: 7 послуг; наступним етапом — 5 сторінок `/services/<slug>`.
- Зараз лише `uk`, перемикач мови лишаємо; EN чекає рішення клієнта. Нову локаль треба додавати без змін у компонентах (SPEC §5).

## Decision
**Контент:**
- Astro content collections з типізованою схемою (zod): `team`, `services`. Файли — Markdown/YAML поруч із картинками.
- Структура за локалями: `src/content/team/uk/<slug>.md`, `src/content/services/uk/<slug>.md`. EN — паралельна папка `en/` з тими самими slug.
- Шаблони `src/pages/team/[slug].astro` (і пізніше `services/[slug].astro`) будуються з колекцій.
- Решта сторінок (головна, про нас, ціни, стерилізація, контакти) — Astro-сторінки, тексти у словниках або у frontmatter колекції `pages` (вирішимо на етапі 2 за обсягом тексту).

**i18n:**
- Вбудований Astro i18n: `locales: ['uk']`, `defaultLocale: 'uk'`, `prefixDefaultLocale: false` → українські URL без змін, EN буде на `/en/...`.
- Тексти інтерфейсу — `src/i18n/uk.json`; хелпер `t(key)` бере локаль з поточного маршруту.
- Один конфіг локалей → маршрути, `<html lang>`, hreflang (з'являється автоматично, коли локалей ≥ 2), sitemap, пункти перемикача мови.
- Додавання EN = `locales: ['uk','en']` + `en.json` + папки `en/` у колекціях. Компоненти не змінюються.

## Options Considered
| | Collections у git (обрано) | Headless CMS (Sanity, Decap тощо) | Хардкод у сторінках |
|---|---|---|---|
| Правки контенту | через git/Claude/розробника | через адмінку | тільки розробник |
| Складність | низька | середня–висока | найнижча |
| Додати лікаря / локаль | файл | запис в адмінці | нова сторінка |
| Вартість | 0 | 0–платно | 0 |

## Consequences
- Новий лікар = один Markdown-файл + фото, шаблон і анімація Team не змінюються.
- Сторінки `/services/<slug>` наступного етапу лягають у готову колекцію.

## Risks / відкрите питання
- **Хто оновлює контент після запуску:** Іван (рішення 30.10.2026). Адмінка не потрібна; контент правиться у файлах колекцій через git. Якщо колись правитиме клініка, git-based CMS додається поверх тих самих колекцій без переробки.

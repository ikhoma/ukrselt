# ADR-0004: Форма — власний endpoint → Telegram Bot API

**Status:** Proposed
**Date:** 2026-10-30
**Deciders:** Іван

## Context
Зараз форма Framer шле дані через вебхук стороннього сервісу (налаштовував знайомий, сервіс невідомий). Вимога: заявка обов'язково приходить у той самий Telegram-чат. Форма: Ім'я (необов'язково), Телефон (обов'язково), без редиректу, мікроанімація кнопки, подія `form_submit` в `dataLayer` (SPEC §7).

## Decision
**Клієнт (у компоненті `Booking`):**
- Нативна `<form>` з `method="post" action="/api/contact"` — працює навіть без JS (тоді сервер повертає просту сторінку-відповідь).
- З JS: `fetch` → стани кнопки idle → sending → success / error (тексти затверджені, SPEC §7.1).
- Подія `dataLayer.push({ event: 'form_submit', service })` — **тільки після успішної відповіді сервера**, щоб не рахувати невдалі відправки як конверсії.
- `service` — ідентифікатор сторінки, на якій стоїть форма (`home`, `contacts`, далі — slug послуги).

**Сервер (`/api/contact`):**
- Валідація: телефон обов'язковий, нормалізуємо до цифр, приймаємо 10–15 цифр; ім'я до 100 символів; екранування HTML.
- Антиспам: honeypot-поле (як у Framer) + мінімальний час заповнення (поле з часом рендеру). Якщо спам з'явиться — додаємо Cloudflare Turnstile або rate limit у Vercel Firewall.
- Відправка: `POST https://api.telegram.org/bot<TOKEN>/sendMessage` у `CHAT_ID`. Текст: ім'я, телефон (клікабельний), сторінка, дата/час (Europe/Kyiv).
- Відповідь JSON `{ ok: true }` / `{ ok: false }`; при помилці Telegram — 502, клієнт показує текст помилки з номером телефону.
- Секрети тільки з env; в логах не пишемо телефони повністю.

## Options Considered
| | Bot API напряму (обрано) | Сторонній сервіс (як зараз) | Email (Resend тощо) |
|---|---|---|---|
| Доставка в Telegram | так | так | ні (потрібен ще міст) |
| Залежності | лише Telegram | невідомий сервіс + доступи знайомого | email-сервіс |
| Контроль формату і помилок | повний | обмежений | повний |
| Вартість | 0 | залежить від сервісу | 0–платно |

## Consequences
- Зникає залежність від стороннього сервісу і чужого акаунта.
- Перед запуском потрібен бот у потрібному чаті (SPEC §7.1, задача перед запуском).

## Risks
- **Єдиний канал доставки.** Якщо Telegram недоступний або бота видалили з чату, заявка губиться. Мітигація: клієнт показує помилку з номером телефону; опційно — дублювати заявки в лог Vercel (без повного телефону) або на email. **Рішення Івана: чи потрібен резервний канал.**
- Бот має бути адміном або учасником чату; для груп `CHAT_ID` від'ємний — перевіряємо тестовою заявкою з preview.

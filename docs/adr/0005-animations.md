# ADR-0005: Анімації — CSS + IntersectionObserver для появ, GSAP для скролу, пружини Framer як криві

**Status:** Proposed
**Date:** 2026-10-30
**Deciders:** Іван

## Context
Анімації переносимо 1:1 (SPEC §4), параметри зняті з Framer:
- appear після прелоадера (затримка 2 с): пружини `bounce 0.2 / duration 0.5`, `bounce 0.2 / duration 0.3`, `stiffness 400 / damping 30 / mass 1`; tween `0.5s [0.44,0,0.56,1]`; y 120/72px.
- поява при скролі, поріг 0.5;
- паралакс (speed 110 / 90 / 95);
- AnimationTimeline (Team — обов'язково, Services — окремим рішенням): rotate −90°, scale 0.5→8, 0→10, 0.9→1, тригери `onScroll`/`onScrollTarget`;
- ротатор слів у hero.

Проблема: Framer використовує фізичні пружини (модель Motion). У GSAP і CSS пружин як таких немає — `ease` там крива, а не фізика.

## Decision
1. **Пружини → криві.** Скрипт збірки обчислює кожну пружину Framer за її параметрами (та сама формула затухаючого осцилятора) і генерує:
   - CSS `linear()` easing для CSS-анімацій появи;
   - GSAP `CustomEase` для анімацій на GSAP.
   Тривалість пружини теж обчислюється (до затухання), а не вгадується. Усі параметри — в `src/scripts/animations.ts`.
2. **Поява (appear і при скролі)** — CSS-класи + один невеликий `IntersectionObserver` (threshold 0.5). GSAP для цього не потрібен.
3. **Паралакс, AnimationTimeline** — GSAP ScrollTrigger (`scrub`). `gsap.matchMedia()` для брейкпоінтів (y 120 / 72 тощо).
4. **Ротатор hero** — CSS (маска `overflow: hidden`, `translateY`), JS лише перемикає слова; таймінги знімаємо з `text-loop` у Framer.
5. **Прелоадер** — готовий SMIL SVG; старт appear-анімацій прив'язуємо до події завершення прелоадера, а не до таймера 2 с, щоб не розійтися при повільному завантаженні. Візуально затримка лишається як у Framer.
6. GSAP завантажується тільки на сторінках, де є скрол-анімації.

## Options Considered
| | Обраний мікс | Усе на GSAP | Motion (motion.dev) |
|---|---|---|---|
| Точність пружин Framer | висока (та сама формула) | висока (з CustomEase) | найвища (та сама бібліотека, що у Framer) |
| JS на сторінці | мінімальний | GSAP скрізь | Motion скрізь |
| Скрол-ефекти (scrub, pin) | GSAP — стандарт | так | слабше |
| Відповідність HANDOFF | так | так | ні |

Motion лишаємо запасним варіантом, якщо криві не дадуть потрібної точності.

## Consequences
- Кожну анімацію звіряємо з живим сайтом (запис екрана або покадрово), як вимагає CLAUDE.md п.6.

## Risks / відкрите питання
- **`prefers-reduced-motion`.** Framer зараз, імовірно, його не враховує. Пропоную для користувачів із цим налаштуванням вимикати паралакс і скрол-трансформації, залишаючи прості появи. Це відступ від «1:1», тому **потрібне рішення Івана.**
- Scale до 8–10× на мобільних може бути важким для GPU; перевіряємо на реальному телефоні.
